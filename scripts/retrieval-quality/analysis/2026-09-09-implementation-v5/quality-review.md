# Implementation work value in frozen v5 trials

This is a descriptive assessment of existing evidence, with no new execution or regrading. All four implementations meet the same mandatory bar: 5/5 source criteria, 4 visible and 20 hidden runtime checks, and integrity passing. Labels map t05→T6, t06→H3, t07→N8, t08→A5. The frozen prompt explicitly requires the API, preserved behavior, original-test migration and accurate runtime-only reporting; added scratch tests are optional and do not increase the mandatory total. Sources: [mapping](../../results/2026-09-09-outcomes-v5/blinding.json); [T6](../../results/2026-09-09-outcomes-v5/quality-T6.json), [H3](../../results/2026-09-09-outcomes-v5/quality-H3.json), [N8](../../results/2026-09-09-outcomes-v5/quality-N8.json), [A5](../../results/2026-09-09-outcomes-v5/quality-A5.json); [prompt](../../outcomes-v4/implement/prompt.md), [rubric](../../outcomes-v4/implement/review-rubric.json). ## Shared value and limits

All four scratch suites add participant-executed checks of empty/no-spawn behavior, acknowledgment classification, wire options, execution/serialization failure, retry/deduplication, cache scoping and capacity. These are useful checks beyond the four supplied visible normalization/scanning tests, but predominantly repeat behavior already required and checked by the controller's [hidden suite](../../outcomes-v4/implement/grader/hidden.test.ts). They do not demonstrate added product capability or higher mandatory correctness. All four specifically test undefined/null subprocess output, which the hidden suite's invalid-ack loop does not directly supply; this is identifiable extra input coverage of an existing requirement, not a new requirement. None adds scratch execution of either actual adapter, original Vitest tests, or semantic TypeScript checking.

## Pair 1: ordinary t05 versus assisted t06

- Six scratch tests in t06 versus five in t05 largely reflects grouping: t05 combines empty/successful transport in one test and puts successful two-event acknowledgment in its invalid-ack test; t06 splits empty, successful and invalid acknowledgments into three. Both cover trailing junk, two-event returned count and a detailed capacity sequence that proves a still-cached second-oldest entry remains suppressed. Test counts alone do not establish broader coverage. [t05 scratch:18](../../results/2026-09-09-outcomes-v5/changes/t05/tests/usage-contract-scratch.test.ts), [t05 scratch:67](../../results/2026-09-09-outcomes-v5/changes/t05/tests/usage-contract-scratch.test.ts), [t06 scratch:16](../../results/2026-09-09-outcomes-v5/changes/t06/tests/usage-request.test.ts), [t06 scratch:77](../../results/2026-09-09-outcomes-v5/changes/t06/tests/usage-request.test.ts).
- t05 explicitly retries both `invalid-ack` and `write-error` result objects, checks valid recorder returns are void, and asserts no writer call for a text part. t06's scratch recorder only injects `invalid-ack`; it checks null filtering and selected normalized token/usage-id fields. t06 tests circular serialization and full mixed-case acknowledgment words; t05 tests a throwing `toJSON` and mixed-case `Recorded`. These are concrete differences in exercised inputs, with no observed correctness separation. The hidden suite already checks circular serialization and both retry reasons; t05's throwing `toJSON` adds a distinct failure route. [t05 scratch:39](../../results/2026-09-09-outcomes-v5/changes/t05/tests/usage-contract-scratch.test.ts), [t05 scratch:50](../../results/2026-09-09-outcomes-v5/changes/t05/tests/usage-contract-scratch.test.ts), [t06 scratch:22](../../results/2026-09-09-outcomes-v5/changes/t06/tests/usage-request.test.ts), [t06 scratch:44](../../results/2026-09-09-outcomes-v5/changes/t06/tests/usage-request.test.ts).
- t06 restores its subprocess spy after each test; t05 uses module mocks without explicit restoration. That is identifiable test-isolation hygiene, but no contamination or prevented failure is demonstrated. [t05 scratch:1](../../results/2026-09-09-outcomes-v5/changes/t05/tests/usage-contract-scratch.test.ts), [t06 scratch:12](../../results/2026-09-09-outcomes-v5/changes/t06/tests/usage-request.test.ts).
- Both adapters and all three original test files are byte-identical between the final candidates. The core differences are equivalent expression/control-flow choices: output conversion, conditional return versus branches, and a named result variable. No extra substantive production behavior is identifiable. [t05 patch](../../results/2026-09-09-outcomes-v5/t05.patch), [t06 patch](../../results/2026-09-09-outcomes-v5/t06.patch).
- t05's final 9-test run follows every edit. t06's one 10-test run precedes formatting edits to core and original tests, with no participant rerun. This is a verification gap, not evidence of a defect; controller checks subsequently pass. ## Pair 2: ordinary t08 versus assisted t07

- Both add five scratch tests. t08 additionally asserts a successful two-event count and exact multi-line JSONL using two distinct events; t07 checks only one-event success/transport. t08 also checks that entry “1” remains cached after entry “0” is evicted; t07 checks only the oldest entry is written again. These are stronger participant assertions in t08, already covered by mandatory hidden tests. t08 varies case across all acknowledgment words; t07 varies `Recorded`. [t08 scratch:26](../../results/2026-09-09-outcomes-v5/changes/t08/tests/usage-write-contract.test.ts), [t07 scratch:23](../../results/2026-09-09-outcomes-v5/changes/t07/tests/usage-contract.test.ts), [t08 scratch:90](../../results/2026-09-09-outcomes-v5/changes/t08/tests/usage-write-contract.test.ts), [t07 scratch:73](../../results/2026-09-09-outcomes-v5/changes/t07/tests/usage-contract.test.ts).
- Both check serialization cycles, one execution on write failure, invalid-part filtering, retry/deduplication, revisions, cwd scoping and independent instances. t08 uses null and asserts void return there; t07 uses a text part and asserts zero calls. Neither scratch suite injects a recorder `write-error` result. These differences do not support an assisted coverage advantage. [t08 scratch:51](../../results/2026-09-09-outcomes-v5/changes/t08/tests/usage-write-contract.test.ts), [t08 scratch:67](../../results/2026-09-09-outcomes-v5/changes/t08/tests/usage-write-contract.test.ts), [t07 scratch:39](../../results/2026-09-09-outcomes-v5/changes/t07/tests/usage-contract.test.ts), [t07 scratch:51](../../results/2026-09-09-outcomes-v5/changes/t07/tests/usage-contract.test.ts).
- Production adapter sources are byte-identical; core differs only in early invalid-output return versus null acknowledgment expression. Original-test differences are import placement and literal `1` versus `events.length` for a fixed one-event fixture. No additional substantive implementation behavior is evident. [t08 patch](../../results/2026-09-09-outcomes-v5/t08.patch), [t07 patch](../../results/2026-09-09-outcomes-v5/t07.patch).
- Both have a final post-edit 9-test run. t07's third run follows only addition of `afterAll` spy restoration; it validates that cleanup but adds no test cases or observed product fix. t08 already restores spies after each test. [t07 scratch:10](../../results/2026-09-09-outcomes-v5/changes/t07/tests/usage-contract.test.ts), [t08 scratch:12](../../results/2026-09-09-outcomes-v5/changes/t08/tests/usage-write-contract.test.ts), [t07 execution_verification](../../results/2026-09-09-outcomes-v5/t07-trace-review.json), [t08 execution_verification](../../results/2026-09-09-outcomes-v5/t08-trace-review.json).

All final reports concisely identify implementation scope and distinguish participant Bun checks from unexecuted Vitest/type validation. t06 explicitly mentions summary preservation, while the other summaries emphasize types/cache/adapter migration; this is useful wording variation, not extra delivered behavior. No report supplies a materially broader diagnostic explanation or claims extra verification. [t05 answer](../../results/2026-09-09-outcomes-v5/t05-answer.md), [t06 answer](../../results/2026-09-09-outcomes-v5/t06-answer.md), [t07 answer](../../results/2026-09-09-outcomes-v5/t07-answer.md), [t08 answer](../../results/2026-09-09-outcomes-v5/t08-answer.md).

The evidence supports useful optional contract verification across both conditions, small input/assertion differences, and no demonstrated extra implementation or reporting value from the assisted trials above the shared mandatory bar. It cannot establish that retrieval caused any choice, that every extra action was valueless, or that broader testing would never find a defect.
