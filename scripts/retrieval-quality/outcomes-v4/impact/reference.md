The factory default is a function value reference, and the actual write invocation is through its parameter; treating only literal calls to recordModelUsage as consumers misses it. The hook's local recordUsage is the returned closure. `createHooks` (154/197) creates the public event hook via `createEventHandler` (432/435); these wrappers establish reachability and lifetime, but createHooks and createEventHandler public signatures do not need changing. The no-argument factory invocation stays valid. `main()` is invoked at the bottom of session-summary.ts, whose Stop entry contract is likewise unchanged. The current local snapshot provides two writer invocation sites (one dynamic parameter invocation and one direct named call) and one production invocation of the returned recorder, not dozens of module-import consumers.

All result objects are truthy. Retaining `!write(...)` would treat unacknowledged results as success and cache failed writes, suppressing retry. Guard on status, not truthiness or mere result presence. Empty events must yield acknowledged/0 without spawning; matching count and zero skips yield acknowledged/input length; malformed/mismatch/nonzero-skips yield invalid-ack; thrown exec/write operations inside recordModelUsage yield write-error with existing debug logging. Do not claim an arbitrary throwing injected writer is newly required to be caught by the recorder: the specified injected contract returns a result and the original factory does not catch injected exceptions.

Keep full normalized event+cwd fingerprinting and oldest-insertion eviction after 1,024 successful fingerprints. Failed results must remain retryable; identical acknowledged snapshots should be skipped; revised counters and different cwd must reach the writer. There is no requirement to key on binary, refresh recency on duplicate hits, redesign the durable identity, or change the void recorder return type. Stop currently ignores the boolean; the proposed status suffix adds visibility while preserving scan fields, Stop/explicit-transcript/binary gates, recursive-summary guard placement and nonblocking hook completion. See model-usage.ts (319–365) and session-summary.ts (108–155).
