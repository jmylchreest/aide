# versioned-docs-generated

**Decision:** Never hand-edit anything under docs/versioned_docs/ — edit docs/docs/ only

## Rationale

docs/versioned_docs/ holds per-release snapshots produced by release tooling: 'make release' generates them locally for new releases, and .github/workflows/docs-version.yml regenerates them for existing tags. A hand-edit there is either overwritten by the next release or silently diverges from the snapshot it claims to be, and it retroactively rewrites what a shipped version documented.

## Details

When a docs change lands, update docs/docs/ (the current, unversioned copy) and stop. Do not mirror the change across the version snapshots, do not 'fix' an inconsistency you spot in an old snapshot, and do not include versioned_docs churn in a feature PR. Snapshots are point-in-time records of what a release shipped with; they are supposed to lag. If a released version's docs are genuinely wrong in a way that matters, that is a release-tooling or re-version task, not a file edit.
