# survey-analyzers

**Decision:** Four survey analyzers: topology (filesystem structure, workspaces, subprojects), entrypoints (code index), churn (go-git history), modules (clustering over the import/reference graph). Adding an analyzer means adding a name constant, never a store schema change.

## Rationale

Covers the onboarding questions: what is this (topology), where do I start (entrypoints), what changes most (churn), how does it decompose (modules). Each reads a different data source - filesystem, tree-sitter code index, git history, import/reference graph. Analyzer names are constants in aide/pkg/survey/types.go and everything downstream keys off them: survey run --analyzer, list/clear filters, stats ByAnalyzer. Supersedes the 2026-03-09 three-analyzer decision, stale since the modules analyzer landed.

## Details

subproject and workspace entries are emitted by the topology analyzer, not a separate one (aide/pkg/survey/subprojects.go). tokens.go is a helper, not an analyzer. Module clustering must obey stored-id-determinism: byte-for-byte stable IDs across runs on an unchanged tree.
