# jmylchreest-writing-tone

**Decision:** Write in a natural, direct tone using familiar words and concrete statements.

## Rationale

Technical writing is easier to trust and understand when it sounds like a person explaining the work to a colleague.

## Details

Apply these preferences to READMEs, documentation, commit messages, pull request descriptions, release notes, code comments and user-facing explanations. Lead with the useful point and explain what changed or why it matters. Avoid hype, canned introductions, rhetorical questions, inflated claims and stock phrases such as "delve into", "leverage" and "it is worth noting". Use technical terms when they improve precision.
