# survey-run-identity

**Decision:** Survey run identity lives in entry metadata (run_commit stamped at run time via survey.StampRunCommit), never in a separate run-metadata bucket. Freshness is computed at read time (capped CommitsBehind walk), never stored. Every analyzer, current and future, must stamp its entries through the same path.

## Rationale

Entries are replaced wholesale per analyzer so all entries share one run; metadata flows through every storage path (direct BoltDB, gRPC daemon, web dashboard) with zero schema or proto change, and unstamped legacy entries degrade gracefully to 'unknown'. A separate run bucket would force proto/gRPC additions for daemon mode. Worktree-dirty flag deliberately omitted: go-git status is O(worktree) and can be very slow; commits-behind covers the practical need. Shipped in 8b155a1; full context in design/module-map-and-survey-freshness.md.
