# terminology-axes

**Decision:** Three orthogonal axes, one word each: scope: = AUDIENCE (injection filter on content; scope:global = inject into all sessions); origin: = PROVENANCE (where an injected record came from: origin:parent:<id>, origin:peer:<name>; synthesized at read time); the topology is the ANCHOR CHAIN (self + parent projects, from aide anchor). Write routing uses --store parent, never --scope. This governs the scope: tag namespace and any --scope flag, not the English word.

## Rationale

scope: shipped as an audience tag (scope:global excluded from share export, injected everywhere) before topology work began; reusing the word for topology or provenance caused repeated design confusion. Package pkg/anchor, type anchorLink, and all docs say anchor chain. Supersedes the 2026-07-21 version, which said scope: was 'the only meaning of the word scope'. Read literally that banned ordinary English and was already violated by unrelated production code, so it could not be enforced - and an unenforceable rule that fires on every review trains reviewers to wave it through.

## Details

Governed: the scope: tag on memories and decisions, and any --scope flag. These mean audience and nothing else - never topology (that is the anchor chain), never provenance (that is origin:). Write routing is --store parent. Not governed: ordinary English use of the word, which has legitimate unrelated meanings already in the tree - findings.RunKey.Scope and AnalyzerStatus.Scope with ScopeProject in aide/pkg/findings/runner.go:20,56,68 mean which files an analyzer run covers; aide/pkg/importresolve/rust.go:108 means Rust lexical scope; 11 skills say 'the scope of a review'. No --scope flag exists in aide/cmd, so that clause is already satisfied. Narrowed 2026-08-25 when the review skill's decision-conformance pass began checking every decision against every diff.
