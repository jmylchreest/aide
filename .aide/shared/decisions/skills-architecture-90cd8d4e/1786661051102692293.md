# skills-architecture

**Decision:** Skill management in the aide Go CLI (aide skill install/uninstall/update/search plus a provider registry) is no longer on the roadmap. Skills stay plain local .md files; the plugin discovers and matches them at runtime, and nothing fetches or manages a registry.

## Rationale

The 2026-03-31 decision planned a Go-side skill manager with pluggable providers (skills.sh, GitHub, self-hosted). Five months on there is no aide skill command and nothing depends on one, so the decision store was carrying roadmap - exactly what no-aspirational-code and the engagement-rules-only store scope both forbid. Dropping it costs nothing because no code was ever written against it. If skill distribution is revisited it starts in FUTURES.md, not here.

## Details

Still in force: src/core/skill-matcher.ts discovers .md files from .aide/skills/, skills/, <plugin-root>/skills/ and ~/.aide/skills/, parses YAML frontmatter (triggers, platforms, requires_binary), fuzzy-matches the prompt (Levenshtein-tolerant) and injects matches. The UserPromptSubmit hot path reads local files only - no network, no registry sync, no fetching in the plugin layer. Project-local skills outrank plugin-bundled, which outrank global ~/.aide/skills/.
