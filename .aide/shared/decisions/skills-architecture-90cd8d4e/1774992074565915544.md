# skills-architecture

**Decision:** Skill management (install, uninstall, update, search, registry) belongs in the aide Go CLI. The TypeScript plugin only handles runtime skill discovery and matching (skill-matcher.ts reads local .md files, matches prompts, injects context). No skill fetching or registry management in the plugin layer.

## Rationale

Separation of concerns: the aide CLI already manages memory, decisions, state, and tasks — skill management fits there. The plugin's hot path (UserPromptSubmit) needs to be fast and only read local files. Remote fetching, registry sync, and provider abstraction are CLI concerns. A built-in aide skill (.md) can bridge the UX so users say 'install the X skill' and the assistant invokes aide CLI commands. The previous skills-registry.ts was dead code in the plugin that conflated these responsibilities — it has been removed.

## Details

Runtime path (plugin): skill-matcher.ts discovers .md files from .aide/skills/, skills/, <plugin-root>/skills/, ~/.aide/skills/. Parses YAML frontmatter for triggers, platforms, requires_binary. Fuzzy-matches user prompts. Injects matching skill content. Management path (Go CLI, future): aide skill install/uninstall/update/search/list. Should support pluggable providers (skills.sh, GitHub, self-hosted registries) via a provider/resolver pattern. Stores installed skill metadata in .aide/ database.
