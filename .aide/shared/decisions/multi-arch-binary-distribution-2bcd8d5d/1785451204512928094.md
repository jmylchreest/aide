# multi-arch-binary-distribution

**Decision:** Ship Go binary via npm optionalDependencies (esbuild-style: 6 per-arch packages @jmylchreest/aide-binary-<platform>-<arch>). OpenCode/Codex get bundled binaries via npm install; Claude Code continues to use download-on-first-use (Claude's marketplace distribution does not support npm optionalDependencies and Claude's version-pinned cache makes the existing pattern bug-free).

## Rationale

Fixes the v0.1.11 bug where install writes binary to /tmp instead of the location MCP actually uses (npm bunx cache differs from install bunx cache). Bundling makes install truly idempotent across MCP launches: the binary is on disk the moment npm install completes. Per-platform split: OpenCode/Codex via npm optionalDependencies (zero-config, offline-after-install, automatic upgrades with npm), Claude Code keeps download-on-first-use (Claude's marketplace plugin format has no optionalDependencies equivalent, and Claude's per-version cache layout means the existing wrapper download pattern already works correctly there). Wrapper gains one bundled-arch candidate path for cross-platform code uniformity. Trade-off: 7 npm publishes per release (1 main + 6 per-arch), ~64MB per arch optional dep (user only downloads the one matching their arch).
