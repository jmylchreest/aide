# multi-arch-binary-distribution

**Decision:** Ship Go binary via npm optionalDependencies (esbuild-style: 6 per-arch packages @jmylchreest/aide-binary-<platform>-<arch>). OpenCode/Codex get bundled binaries via npm install; Claude Code continues to use download-on-first-use. Resolution MUST follow node algorithm (require.resolve + node_modules walk-up), not <plugin-root>/node_modules.

## Rationale

Fixes the v0.1.11 bug where install writes the binary to /tmp instead of the location MCP actually uses (npm bunx cache differs from install bunx cache). Bundling makes install truly idempotent across MCP launches: the binary is on disk the moment npm install completes. Per-platform split: OpenCode/Codex via npm optionalDependencies (zero-config, offline-after-install, automatic upgrades with npm), Claude Code keeps download-on-first-use because its marketplace plugin format has no optionalDependencies equivalent and its per-version cache layout already makes the wrapper download pattern correct. Node-algorithm resolution is required because the plugin can be hoisted or nested anywhere in a consumer tree - assuming <plugin-root>/node_modules reintroduces the same class of wrong-path bug. Trade-off: 7 npm publishes per release (1 main + 6 per-arch), ~64MB per arch optional dep, of which a user downloads only their own.

## Details

Restated 2026-08-13 to carry forward the rationale that the 2026-07-31 version dropped when it added the resolution rule. Packages: packages/aide-binary-{darwin,linux,windows}-{amd64,arm64}.
