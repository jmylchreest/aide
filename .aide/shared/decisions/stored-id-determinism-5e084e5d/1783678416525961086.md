# stored-id-determinism

**Decision:** Any code that stores derived IDs or groupings (module clustering, community assignments, and successors) must be deterministic byte-for-byte across runs on an unchanged tree, and must remap IDs to the previous persisted assignment on re-run. No randomness, no map-iteration-order dependence, total-order tiebreaks everywhere.

## Rationale

Non-reproducible derived output reads as massive churn in every diff and injection even when the underlying grouping is identical - it is a bug, not a tuning issue. Determinism also makes golden tests possible and keeps run diffs (survey_run +added/-removed) meaningful. Applies today to survey entries and code-index-derived output; becomes load-bearing for the planned modules analyzer (design/module-map-and-survey-freshness.md).
