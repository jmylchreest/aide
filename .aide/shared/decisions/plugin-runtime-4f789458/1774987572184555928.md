# plugin-runtime

**Decision:** Use bun as the runtime for all plugin and web UI TypeScript code. No bash/shell scripts for runtime code paths.

## Rationale

Windows compatibility: bash scripts (.sh), Unix tools (flock, readlink, which), and shell redirections (2>/dev/null) don't work on Windows. Bun runs TypeScript natively on all platforms (Linux, macOS, Windows) and is already a build-time dependency. Use the 'which' npm package (224M downloads/week, npm-maintained) for cross-platform binary PATH lookups instead of execSync with 'command -v' or 'where'.

## Details

Applies to: plugin hooks, MCP server wrapper, HUD scripts, binary downloader, skill matcher, session hooks. Does NOT apply to: Go backend (aide binary), dev-only tooling (aide-dev-toggle.sh, test scripts), or build configs (Makefile, goreleaser). Key patterns: (1) plugin.json commands use 'bun' as the command with .ts file as arg, (2) no 2>/dev/null or other shell syntax in hook commands, (3) use 'which' package instead of execSync/execFileSync with which/where/command-v, (4) use process.platform checks for platform-specific logic like .exe extensions.
