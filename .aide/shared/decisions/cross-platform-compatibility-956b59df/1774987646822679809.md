# cross-platform-compatibility

**Decision:** All plugin runtime code must work on Linux, macOS, and Windows. All plugin/MCP integration code must work with both Claude Code and OpenCode.

## Rationale

Users run aide on all major platforms and with different AI assistants. Windows was broken because bash scripts and Unix tools were used in runtime paths. OpenCode and Claude Code have different plugin mechanisms but share the same core TypeScript code.

## Details

Platform rules: (1) Never use Unix-only tools (flock, readlink -f, chmod +x) in runtime code — use Node/Bun APIs instead. (2) Always account for .exe suffix on Windows when constructing binary paths (process.platform === 'win32'). (3) Use the 'which' npm package for PATH lookups — never execSync with 'command -v', 'which', or 'where'. (4) No shell syntax (2>/dev/null, pipes, &&) in plugin.json hook commands — these are interpreted differently on Windows. (5) Use path.join() for all file paths, never string concatenation with '/'. (6) Use fs.realpathSync() instead of shell readlink/realpath. Assistant rules: (1) src/core/ contains shared code used by both Claude Code and OpenCode — changes here affect both. (2) src/hooks/ is Claude Code specific. (3) src/opencode/ is OpenCode specific. (4) packages/opencode-plugin/ is rebuilt from src/ via copy-src.mjs — fix the source, not the copy. (5) Test changes on the platform-agnostic code paths, not just the current OS.
