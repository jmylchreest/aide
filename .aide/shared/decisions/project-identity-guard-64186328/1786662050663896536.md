# project-identity-guard

**Decision:** Never let ~/.aide/ anchor a project: skip it as a project marker during walk-up unless cwd is $HOME itself, and validate that the resolved project root is an ancestor of cwd before injecting memory.

## Rationale

~/.aide/ holds global config (skills, MCP) written by the TS layer; matching it during walk-up anchors every session at $HOME and contaminates memory across projects. Two guards: findProjectRoot skips ~/.aide/ when cwd is not $HOME (but always matches ~/.git/ so dotfile repos still work), and validateProjectRoot refuses injection when cwd sits outside the resolved root. Rename-tolerant: no project name is stored.

## Details

Go resolver: findProjectRoot in aide/cmd/aide/main.go; injection guard: validateProjectRoot in aide/cmd/aide/cmd_session.go. TS mirror: findProjectRoot in src/lib/project-root.ts, which uses os.homedir() and must stay behaviourally identical to the Go resolver. A stray child .aide/ cannot shadow a real root: VCS-marker candidates are preferred over .aide-only candidates during the walk-up.
