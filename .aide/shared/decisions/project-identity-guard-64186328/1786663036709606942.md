# project-identity-guard

**Decision:** Never let ~/.aide/ anchor a project: skip it as a project marker during walk-up unless cwd is $HOME itself, and validate that the resolved project root is an ancestor of cwd before injecting memory.

## Rationale

~/.aide/ holds global config (skills, MCP) written by the TS layer; matching it during walk-up anchors every session at $HOME and contaminates memory across projects. Two guards: the resolver skips ~/.aide/ when cwd is not $HOME (but always matches ~/.git/ so dotfile repos still work), and validateProjectRoot refuses injection when cwd sits outside the resolved root. Rename-tolerant: no project name is stored.

## Details

Single resolution authority: resolveAnchor in aide/cmd/aide/cmd_anchor.go. findProjectRoot in main.go is a thin wrapper over it - add resolution logic to neither. TS mirror: findProjectRoot in src/lib/project-root.ts, which uses os.homedir() and must stay behaviourally identical to resolveAnchor. Injection guard: validateProjectRoot in aide/cmd/aide/cmd_session.go. A stray child .aide/ cannot shadow a real root: .aide-only candidates apply only when no VCS marker exists anywhere in the ancestry. Enforced in CI and pre-commit by scripts/check-resolver-guards.ts, which fails on new inline resolution logic outside the allowlist.
