# jmylchreest-writing-comments

**Decision:** Write comments that explain intent, constraints or surprising behaviour.

## Rationale

Comments are most useful when they preserve information that the code alone cannot convey.

## Details

Use concise, complete sentences for explanatory comments and docstrings. Avoid narrating obvious code or adding boilerplate commentary. Keep comments accurate when behaviour changes. Follow required documentation formats and preserve machine-readable directives.
